# lab/ — наши расширения Open WebUI

Тулзы, функции и скрипты, которыми мы превращаем Open WebUI в кокпит LLM/RL-инженера:
подключаем свои чекпойнты, отлаживаем модель, смотрим роллауты, отдаём знание из скиллов.

Ветка форка запинена на тот же коммит, что крутится у нас в контейнере
(`01f4282`, версия 0.11.0), поэтому код в `backend/` и `src/` совпадает с реально
работающим инстансом. Проверять поведение можно прямо по исходникам в этом же дереве.

## Структура
```
lab/
  tools/       # OWUI Tools (класс Tools) — то, что модель вызывает как функции
    llm_debug.py      отладка модели: confidence heatmap, near-miss, tool choice, схемы, циклы
    diagram_tool.py   диаграммы: mermaid инлайн + SVG в панель артефактов
    magic_tool.py     минимальный пример тулзы (проверка проводки)
  functions/   # Pipe/Filter функции (класс Pipe / Filter) — свой харнесс и перехват
    harness_qwen38.py свой ReAct-луп поверх eliza-слага, виден в селекторе как модель
  scripts/
    install_tool.sh   поставить тулзу + завести workspace-модель с привязкой + refresh
    skill_to_tool.py  сгенерировать тулзу из нашего скилла (SKILL.md + references/)
  docs/        # заметки по механикам
```

## Установка в работающий инстанс
```bash
# тулза + модель с привязкой (один шаг)
./scripts/install_tool.sh tools/llm_debug.py llm_debug qwen38-27b-gate

# любой наш скилл -> тулза
./scripts/skill_to_tool.py ~/.claude/skills/agentic-benchmarks --id bench_knowledge --install
```
Несколько тулзов на одну модель: правь `meta.toolIds` (эндпоинт `/models/model/update`
в 0.11 отдаёт 500 на частичном теле, проще поправить `meta` в БД и дёрнуть `?refresh=true`).

## Что уже проверено вживую (и стоило времени)
- **Проверять тулзы надо В БРАУЗЕРЕ.** `curl /api/chat/completions` это OpenAI-passthrough:
  он вернёт `tool_calls` сырыми и НЕ исполнит их. Серверный tool-loop
  (`process_chat_response` -> `execute_tool_call`) работает только в UI-контуре
  (есть `session_id` и сокет).
- **Тулза не может дорисовать в ответ через `__event_emitter__`.** Событие
  `{"type":"message"}` аппендит контент (`Chat.svelte:999`), но при завершении контент
  перезаписывается из структурированного `output` (`Chat.svelte:2377`). Рабочий способ:
  вернуть готовый блок как РЕЗУЛЬТАТ и потребовать вывести дословно.
- **Рендер:** ` ```mermaid ` рисуется инлайн, ` ```html ` уходит в панель артефактов
  (iframe, живой JS), ` ```vega-lite ` даёт график.
- **После создания модели обязателен `GET /api/models?refresh=true`**, иначе `Model not found`.
- **Установка плагина прямым INSERT в sqlite молча ломается:** штатный create считает
  `specs` из кода, а без них модель тулзу никогда не вызовет. Ставить через API.

## Что даёт наш серв (замерено на eliza -> sglang, Qwen3.8-27B)
| Есть | Нет |
|---|---|
| `logprobs` + `top_logprobs` (в том числе во время tool-call) | `cached_tokens`, prefix-cache hit rate |
| `usage.reasoning_tokens` отдельно от completion | KV-cache и состояние очереди |
| `finish_reason` / `matched_stop` (видно тихую обрезку по `length`) | TTFT/prefill из ответа (только замер клиентом) |
| `metadata.weight_version` (сейчас `"default"`) | |

`weight_version` стоит выставлять на серве в реальный id чекпойнта: тогда каждый ответ
самоидентифицируется, и собранные оценки становятся пригодны как датасет.

Замер стоимости инструментов: три тривиальных тулзы добавили **~400 токенов** к промпту,
то есть примерно 130 токенов на инструмент за КАЖДЫЙ запрос. Неиспользуемые тулзы это
чистый налог на контекст, `inspect_tool_choice` его показывает.

## llm_debug: что показывает
- `inspect_confidence(prompt)` — ответ, раскрашенный по уверенности токенов, средняя
  уверенность, число неуверенных мест, флаг обрезки, и таблица «почти выбрал другое»
  (где отрыв лидера от второго кандидата меньше 1.2 логпроба).
- `inspect_tool_choice(prompt, tools_json)` — какой инструмент позван и с какой
  уверенностью на токенах имени, что почти позвал вместо, валидация аргументов против
  JSON-схемы (пропущенные обязательные, лишние поля, невалидный JSON, несуществующее имя),
  стоимость схем в токенах, список неиспользованных тулзов, флаг протечки XML мимо парсера.
- `detect_tool_loops(trace_json)` — повторные вызовы с теми же аргументами и пинг-понг
  между двумя инструментами.
