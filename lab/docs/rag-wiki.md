# Поиск по нашей вике прямо в чате

Внешнего веб-поиска у нас нет и не будет: сеть закрыта. Зато есть своя база знаний, и
OWUI умеет искать по ней локально. Собрали коллекцию из вики, траблшутинга и доков
кокпита — 28 документов, 439 КБ. В чате вызывается через `#`, ответ приходит со
ссылкой на файл-источник.

Проверено на демо: вопрос «Ган падает с exit code 37, что проверять?» → ответ по
раннбуку `training-ops-diagnostics.md` с маркером источника.

## Как поставить

```bash
./setup_rag.py --stage        # один раз: положить эмбеддер в кэш контейнера
./setup_rag.py --apply        # переключить эмбеддер и переиндексировать
./setup_knowledge.py --apply  # залить документы (идемпотентно, по хешу)
./setup_rag.py --check        # прогнать eval поиска
```

На VM то же самое с `--ssh qwenweb.vla.yp-c.yandex.net --host http://qwenweb.vla.yp-c.yandex.net:3000`.

## Три грабли, на которых потеряли время

**1. Дефолтный эмбеддер понимает только английский.** OWUI из коробки ставит
`all-MiniLM-L6-v2`. Наши документы и вопросы русские, и поиск работал как повезёт.
Улика была однозначная: один и тот же вопрос про eliza **по-английски** находил нужный
раннбук, **по-русски** выдавал ROADMAP. Дословная русская фраза свой документ находила
(совпали токены), осмысленный русский вопрос — нет.

Лечение: `paraphrase-multilingual-MiniLM-L12-v2` (477 МБ, 384 измерения, префиксы не
нужны). После замены eval даёт 6/6 против 1/6.

**2. `HF_HUB_OFFLINE=1` — это МЫ сами.** Переменной нет в образе, её ставит наш
`docker run` по рецепту `team-chat-serve` (тогда HF-CDN с VM был закрыт, и без офлайна
контейнер вис на старте). Побочный эффект вылез сейчас: смена модели через UI или API
ничего не качает и тихо оставляет систему **без эмбеддера вообще**. Сеть при этом
живая — `curl` до huggingface.co из контейнера отдаёт 200, а питоновский клиент просто
не имеет права ходить. Поэтому модель кладём в кэш снаружи (`--stage` качает там, где
интернет есть, и заливает архивом). Снимать офлайн-флаг ради этого не стоит: пересоздавать
контейнер дороже, а офлайн ещё и страхует от зависания на старте.

Из образа при этом приезжает `RAG_EMBEDDING_MODEL=all-MiniLM-L6-v2` — тот самый
англоязычный дефолт из пункта 1.

Отдельно: на VM кэша эмбеддингов не было вообще (образ переносили руками), так что
там не работал даже дефолтный английский — коллекция просто не индексировалась.

**3. `/knowledge/reindex` отвечает `true`, даже когда упали все файлы до одного.**
Единственный честный признак — строка `No embedding model is loaded` в логах. Причём
смотреть надо **с отсечкой по времени**: `docker logs --tail N` показывает ошибки
прошлых попыток, и на этом легко принять старую ошибку за свежую (приняли).

## Eval поиска

В `setup_rag.py` лежит набор из 6 вопросов, для каждого ответ точно есть в конкретном
файле — проверено грепом по вике, а не на глаз. Без такого набора любая правка настроек
RAG обсуждается вслепую. Сейчас 6/6 и на локальном инстансе, и на демо.

Заодно проверили, что здоровенный `gotchas.md` (225 КБ) не забивает выдачу: вопросы,
ответы на которые лежат в маленьких файлах (`run-sft.md` 1.3 КБ,
`qyp-vm-ssh-permission-denied.md` 3.5 КБ), находят именно их.

## Чего в коллекции нет

Eval выявил не только проблему поиска, но и **дыры в самой вике**: два вопроса не
находили ответа, потому что ответа там не было. Первый про регистрацию собственного
чекпойнта в шлюзе (раннбук описывал только клиентскую сторону), второй про залипание
деплоя среды из-за потолка операций в пуле (не было ни строчки). Оба пробела закрыты,
знание просто жило не в вике.

Отдельная деталь, на которую напоролись сразу же: **этот файл сам стал помехой поиску**,
пока в нём стояли формулировки вопросов дословно. Документ про дыры выигрывал выдачу у
документов с ответами. Поэтому вопросы здесь пересказаны, а не процитированы.

**Транслитерация не работает.** Запрос «элиза» не находит раздел, где написано `eliza`:
модель эти написания не связывает. Дёшево лечится в самом документе — обе формы в
заголовке (так и сделано в `runbooks/eliza.md`).

## Пресет «Вика-помощник»

Чтобы не требовать от людей помнить про `#`, коллекция прицеплена к пресету модели.
Две неочевидности:

* **`function_calling` должен быть `legacy`.** `middleware.py` разворачивает
  `meta.knowledge` в файлы запроса ТОЛЬКО в legacy-режиме; при `native` коллекция
  игнорируется молча, без единой ошибки. Тулзов у пресета нет, терять нечего.
* **Пресет стоит на RL v7, а не на базе.** На одном и том же вопросе по вике база
  выдала 2267 символов англоязычного черновика рассуждений, v7 — 238 символов
  готового ответа со ссылкой. Это тот же протекающий reasoning, что и везде: серв
  запущен без `--reasoning-parser`.

Дефолтный RAG-шаблон тоже заменён: 1445 символов английских инструкций модель
пересказывала вслух вместо ответа. Свой короче и по-русски. `TOP_K` поднят 3→5, а
`CHUNK_SIZE` 1000→2000: наши разделы длиннее тысячи символов, и при мелких чанках в
выдачу попадал симптом, а способ починки уже нет.

Отсюда правило для авторов вики: **пиши раздел ответом вперёд**. Строчка «Коротко:
сделай то-то» в начале попадает в тот же чанк, что и заголовок, и доезжает до модели.

## Что осознанно НЕ индексируем

Личные заметки (`~/.claude/.../memory/`) в коллекцию не идут. Демо на VM открыто
команде по корп-URL, и туда должны попадать только командные документы.
