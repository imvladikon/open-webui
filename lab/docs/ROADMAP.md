# Кокпит: анализ пробелов и план развития

Состояние на 2026-08-16. Что уже стоит: tools `diagram_tool`, `llm_debug`, `bench_knowledge`;
functions `run_metadata` (filter), `inspect_actions` (action), `autocontinue`, `project_gen`,
`serve_status` (pipes); скрипты registry/import_rollout/export_feedback/setup_arena/skill_to_tool/
provision/secure_relaunch. Рендер проверен: LaTeX, CodeMirror-подсветка с Run/Save/Copy, mermaid,
HTML-артефакты, кнопки контента.

## Сквозной урок (три бага подряд из одной ошибки)
Нельзя заставлять модель ДОСЛОВНО копировать большой payload: она упирается в max_tokens и
обрывается. Так сломались `draw_svg` (17 КБ HTML), `llm_debug` (vega-спека на 120 точек) и
длинные code-ответы. **Правило: всё крупное уходит файлом через Files API, в чат — 1-3 строки
и ссылка.** Все новые фичи проектировать сразу так.

## Пробелы (по убыванию ценности)

### P0. Нет фейловера между слагами
Все тулзы и пайпы прибиты к `qwen38-27b-gate`. Сейчас (проверено) qwen38 лежит, v7 работает —
и весь кокпит нерабочий, хотя живая модель есть. Надо: общий резолвер «взять первый живой слаг
из списка», плюс понятная ошибка вместо молчания.

### P1. Нечем гонять регресс-набор
Нет способа прогнать фиксированный список промптов по чекпойнту и сравнить с прошлым прогоном.
Это базовая нужда при пострейне. В OWUI есть Automations, но они про cron, не про сравнение.

### P1. Не видно бюджета контекста
Инженер не видит, сколько токенов съели системный промпт, схемы тулзов, история и RAG. У нас
уже замерено, что тулзы стоят ~130 токенов каждая, но в UI этого нет.

### P2. Нет разброса сэмплов
Один промпт × N сэмплов × разные температуры в одну таблицу — быстрый способ увидеть
mode-collapse у чекпойнта. Сейчас только вручную по одному.

### P2. Нет экспорта диалога
Нельзя одним кликом забрать чат как markdown/JSON (для тикета, для отчёта, для датасета).

### P2. Нет GPU-пульта в чате
`serve_status` показывает слаги, но не отвечает на «а есть ли вообще свободные GPU и чем пинить».
У нас есть скилл gpu-watch, его знание не проброшено в чат.

### P3. Судья и RCA не подключены
Наш booking-judge и RCA-пайплайн живут вне чата. Логично дать кнопку «оценить этот диалог».

### P3. Диаграммы только mermaid + сырой SVG
Нет graphviz/plantuml, нет графиков из данных (vega есть в рендере, но нет тулзы, которая
строит спеку из CSV/JSON пользователя).

### Чего в 0.11 нет и не будет без форка фронта
diff двух ответов; таблица результатов регресс-прогона внутри UI; своя причина в оценке;
read-only чат; постоянный бейдж метаданных (только тултип и statusHistory).

## План (итеративно, каждый пункт проверяется эмпирически)

| # | Что | Зачем | Нужен живой серв для проверки |
|---|---|---|---|
| 1 | **Резолвер живого слага** во всех тулзах/пайпах | кокпит работает, пока жив хоть один чекпойнт | да (частично: проверяется при одном лежащем) |
| 2 | **`chat_export`** action: диалог → markdown-файл | забрать в тикет/отчёт/датасет | нет |
| 3 | **`gpu_status`** pipe: свободные healthy-GPU по сегментам | понять, почему серв не поднимается | нет (YT, не модель) |
| 4 | **`context_budget`** тулза: разбивка промпта по токенам | видеть налог схем и истории | да |
| 5 | **`sampling_spread`** тулза: N сэмплов × температуры | ловить mode-collapse | да |
| 6 | **`regression.py`** скрипт: набор промптов → прогон → сравнение | пострейн-регресс | да |
| 7 | **`plot_data`** тулза: CSV/JSON → vega-lite график | графики из чисел прямо в чате | нет (спека маленькая) |
| 8 | судья/RCA как тулза | оценка диалога по нашим осям | да |

Порядок выбран так, чтобы ночью (сервы флапают) сначала шли пункты, проверяемые без модели.

## Статус после ночной итерации (2026-08-17)

Сделано и проверено вживую:
- **P0 фейловер между слагами** — кокпит жив, пока жив хоть один чекпойнт.
- **Экспорт диалога** (md/jsonl), **GPU и пул в чате**, **бюджет контекста**, **разброс сэмплов**,
  **график из данных** — всё из первоначального плана.
- **Паритет с ChatGPT**: включены память, автодополнение, компакция (были выключены в коде).
- **Проекты** на папках с системным промптом (Booking RL / Бенчмарки / Инфра / Черновики).
- **Регресс-набор** с сравнением прогонов и exit-кодом для CI.
- **A/B двух чекпойнтов** одним промптом со своими параметрами у каждого.
- **Библиотека промптов**: /rca /bench /serve /diag /short /review.
- **Свёртка рассуждений** + найденная корневая причина протечки (серв без reasoning-parser).

Осталось из плана:
- судья/RCA как тулза (нужен доступ к нашему judge-эндпоинту);
- контрфактический реплей трейса (правка результата тула + regenerate);
- голос, картинки, веб-поиск — упираются во внутренние бэкенды, не в код.

Требуют решения человека (не делаю сам):
- стабильность сервов: вес 10 против гарантийной квоты (вес влияет на джобы коллег);
- гейт-тест `--reasoning-parser` на одном серве (раньше он опустошал content и ломал бенчи);
- секьюрный перезапуск командного чата (нужны сервисный токен, CORS-origin, способ auth).
